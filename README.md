# ufw_accesser

Автоматическая настройка брандмауэра UFW по списку доменных имён и IP-адресов.
Скрипт превращает текстовый файл правил в актуальные правила `ufw`, постоянно
проверяет DNS и обновляет правила, если IP-адреса доменов изменились.

## Задумка

Вместо того чтобы вручную переводить доменные имена в IP-адреса и вбивать
десятки команд `ufw allow from …`, вы ведёте один файл правил, в котором
указываете домены (или IP) и желаемый доступ. `ufw_accesser` сам:

- переводит домены в актуальные IP через `host`;
- создаёт правила `allow`/`deny`/`icmp` в правильном формате;
- помечает каждое правило комментарием `accesser:[...]`, чтобы отличать их от
  ручных;
- удаляет устаревшие правила, если домен больше не фигурирует в файле правил
  или сменил IP;
- синхронизирует брандмауэр каждые 5 минут через cron.

## Установка

```bash
git clone https://github.com/Tutkis/ufw_accesser.git
cd ufw_accesser
sudo ./setup.sh
```

## Запуск по одной команде

Установить и настроить UFW можно прямо сейчас — одна команда:

```bash
curl -fsSL https://raw.githubusercontent.com/Tutkis/ufw_accesser/main/setup.sh | sudo bash
```

`curl -fsSL` обеспечивает проверку кода, сжатое скачивание и тихий режим (ошибки выводятся явно).

`setup.sh` устанавливает зависимости (`ufw`, `openssh-server`, `dnsutils`),
создаёт каталог `/opt/accesser`, генерирует шаблон `/opt/accesser/rules` и
скрипт обновления `/opt/accesser/update.sh`, запускает первоначальную
синхронизацию и настраивает cron-задачу.

## Формат файла правил

Файл `/opt/accesser/rules` состоит из двух блоков. Строки, начинающиеся с `#`,
игнорируются.

### Блок псевдонимов (алиасов)

```
alias | <имя> | <порт>/<протокол>
```

Примеры:

```
alias | ssh      | 22/tcp
alias | http     | 80/tcp
alias | https    | 443/tcp
alias | proxy    | 8080/tcp
alias | wireguard| 51820/udp
```

### Блок правил доступа

```
<allow|deny|icmp> | <источник> | <назначение>
```

- `<источник>` — домен, IP-адрес или `any`.
- `<назначение>` — имя псевдонима или `port/proto`. Для `icmp` — `any`.

Примеры:

```
allow | any               | http
allow | any               | https
allow | internal.tutkis.ru| proxy
deny  | 192.168.10.50     | ssh
icmp  | monitor.tutkis.ru | any
```

> **Внимание:** `setup.sh` определяет порт SSH из `/etc/ssh/sshd_config` только
> при первом запуске. Если вы меняете порт SSH в `sshd_config` (например, на
> `2222`), вручную обновите строку `alias | ssh | 22/tcp` в `/opt/accesser/rules`
> — иначе правила могут создаваться не для актуального порта.

## Пример конфигурации для домена mydomene.com

Допустим, на хостинге `mydomene.com` развёрнуты SSH, веб-сервер, прокси и
WireGuard, ICMP-тестирование ведётся с монитора `monitor.mydomene.com`.

```
# ------------------------------------------------------------------
# Псевдонимы портов
# ------------------------------------------------------------------
alias | ssh      | 22/tcp
alias | http     | 80/tcp
alias | https    | 443/tcp
alias | proxy    | 8080/tcp
alias | wireguard| 51820/udp

# ------------------------------------------------------------------
# Правила доступа
# ------------------------------------------------------------------
# Любой может подключиться к веб-серверу
allow | any               | http
allow | any               | https

# SSH — только администраторам с корпоративного домена
allow | admin.mydomene.com      | ssh

# Прокси — только из офиса
allow | office.mydomene.com     | proxy

# WireGuard — только наше VPN-приложение на другом сервере
allow | vpn-gw.mydomene.com     | wireguard

# Блокируем одного вредоносного клиента
deny  | badactor.example.net    | ssh

# ICMP-тестирование с сервера мониторинга
icmp  | monitor.mydomene.com    | any
```

После каждого изменения файла правил достаточно перезапустить cron или
запустить вручную:

```bash
sudo /opt/accesser/update.sh
```

## Работа скрипта

`/opt/accesser/update.sh` читает файл правил, разворачивает алиасы в
`порт/протокол`, переводит домены источников в IP и применяет правила.
Каждое созданное правило помечается комментарием вида:

```
accesser:[allow][admin.mydomene.com][ssh]
```

При перезапуске скрипт сравнивает текущие правила `ufw` с файлом правил и
удаляет те, которых больше нет в списке, или у которых изменился IP-адрес.

## Зависимости

- `ufw` — брандмауэр;
- `dnsutils` (утилита `host`) — разрешение доменных имён;
- `openssh-server` — устанавливается автоматически при необходимости;
- запуск от `root` (через `sudo`).

## Проверка

После настройки брандмауэра убедитесь, что SSH не закрыт, и проверьте
актуальные правила:

```bash
sudo ufw status verbose
```

Правила, созданные `ufw_accesser`, видны по метке `accesser:` в столбце
`Comment`.
